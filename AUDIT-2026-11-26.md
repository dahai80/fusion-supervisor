## Needs review — NOT fixed (risk/change-of-behavior)

### R1. `restart_after_stop` env gap — src/supervisor/mod.rs (restart path), HIGH
RPC `restart <svc>` env only gets `shell_env_for` + overlay, missing `native_env_for` (DATABASE_URL/REDIS_URL/QDRANT_URL) — unlike up/crash-restart paths. The 4 `needs_injection` services (identity/rag/cowork/model-hub) restart without sidecar env; adjacent comment claims parity with the crash closure (doc lie). Same silent-SQLite-fallback bug class as issue #78.
Action: add `native_env_for` (+ same ERROR-and-continue semantics) in `restart_after_stop`. Risk: confirm upstream start.sh doesn't self-source these vars first.

### R2. `StartJob::run` timeout can never fire — src/supervisor/mod.rs (StartJob, up_native exec), HIGH
`start_fn` is a purely synchronous closure (blocking `child.wait()`), so the `tokio::time::timeout` around it polls-complete in one poll — `start_timeout_sec` is dead protection; a hung start.sh holds the core lock forever under up_all/up_boot_set.
Action: run the closure via `spawn_blocking`, apply timeout to the JoinHandle. Risk: long go-build start scripts would now genuinely bail at the timeout.

### R3. #101 health audit key injection unreachable — src/env_map.rs (shell_env_for), HIGH
`FUSION_HEALTH_AUDIT_HMAC_KEY` injection was added inside `shell_env_for` before the gate, but both call sites only call it when `needs_shell_env(svc)` — and `shell_vars("fusion-health")` is empty, so the branch never runs. Supervisor-injected audit key independence documented in CLAUDE.md does not exist (upstream start.sh self-sourcing is what keeps it working today).
Action: call `health_audit_key()` directly at env-assembly sites + regression test.

### R4. UDS/HTTP `logs` runs blocking subprocesses under the core lock — src/rpc/server.rs (Logs arm), HIGH
`compose_logs` (docker compose logs) + `tail` execute while holding the core mutex — violates the documented lock discipline; slow docker blocks all RPC/HTTP/tick.
Action: resolve log source under lock, exec outside. Needs small refactor (compose handle access).

### R5. Logs filename mismatch for sub-services — src/rpc/server.rs vs src/start_map.rs, MEDIUM
Log writer uses service name (`fusion-cowork-ws.log`), RPC `logs` reader resolves via `name_to_dir` → reads `fusion-cowork.log` (0B). Affects cowork-ws, office-api, trainer-bridge, drama-backend, osagent-metrics, model-hub, multi-node.
Action: reader should use `start_map::log_path(svc)`; fix CLAUDE.md log-path claim.

### R6. manifest exception doubly stale — src/manifest.rs (`fusion-code-modelization`), MEDIUM
Registry key is `fusion-code-modenization`, on-disk repo is `fusion-code-modelization` — the EXCEPTIONS tuple matches a key that never occurs; `name_to_dir` falls through to a nonexistent dir (port-orphan ownership check can never match).
Action: flip the tuple after confirming disk spelling is authoritative.

### R7. ai-trysuite dead rows — probe_map.rs / manifest.rs / env_map tests, MEDIUM-LOW
Service no longer in port-registry.yaml (repo dir still exists). Dead table rows; harmless today.
Action: remove rows (or re-register service upstream).

### R8. HTTP partial-read — src/http_server.rs (handle_conn), MEDIUM
Single `stream.read` per request; POST body split across TCP segments parsed truncated (spurious 400 / lost token). No Content-Length handling; >8192 silently dropped.
Action: loop until `\r\n\r\n`, then read body per Content-Length (413 over cap). Small rewrite of the read loop.

### R9. compose_tracker transitional reset — src/compose_tracker.rs (observe), MEDIUM
`(Some(_), _)` arm resets fail_count/escalated during Starting/Restarting — flapping Failed→restarting→Failed never accumulates, CrashLoop latch deferrable indefinitely; escalated latch lost without a Back alert. Contradicts the stated "恢复后重置" rule.
Action: only reset in the Healthy arm. Needs owner decision on intended semantics.

### R10. Skip-healthy probe is TCP-only — src/supervisor/mod.rs (up paths), MEDIUM-LOW
`ProbeSpec::tcp(d.port)` used for skip detection: UDS/PidFile/port-0 services (link, desigma, projects) never detected as up → every `up` re-executes their start.sh (usually no-op thanks to pidfile check, but defeats double-start avoidance).
Action: use `probe_map::probe_spec_for(name, port)` for the skip check.

### R11. Tray self-heal spawns one-shot `fusion-sv up` — tray/src/main.rs, MEDIUM
In the unreachable-daemon scenario (the button's precondition), the spawned `up` client exits code 3 immediately; the daemon is never started by the button.
Action: spawn `fusion-sv daemon` instead, or retry `up` until /health responds.

### R12. Ops page unreachable from shell — web/manifest.json, MEDIUM-LOW
Manifest declares 3 pages; SPA has a 4th (`/ops` — boot tiers/pins/backup). Shell page registry never shows Ops.
Action: add `{"route":"/ops",...}` or document why hidden.

### R13. `cancel_drain` unreachable from any face — src/supervisor/mod.rs, LOW
Issue #9 primitive has no UDS/HTTP/CLI caller; only tests. Expose (RPC method/POST route) or mark test-only.

### R14. env_file parsing vs dotenv semantics — src/env_map.rs (read_env_file), LOW
No quote stripping / inline-comment truncation: `KEY="secret"` yields literal quotes. Nothing broken today (.env.example unquoted) but diverges from docker dotenv.
Action: strip matching quotes + unquoted-`#` truncation (or document).

### R15. Release ships no tray binary — .github/workflows/release.yml, LOW
Only fusion-sv artifacts; tray is local-build-only while docs present it as a normal build product. Ship a macos-aarch64 tray artifact or document the intent.

### R16. CI has no web job — .github/workflows/ci.yml, LOW-IMPACT
web/dist ships to production via web_dir static serving but nothing runs `bun run typecheck`/`build` in CI.
Action: add a web job gated on `web/**` paths.

### R17. Stale superpowers plan artifact — docs/superpowers/plans/2026-09-01-container-multinode-deploy.md, LOW
Leftover SDD planning doc, no consumers; docs.yml explicitly skip-dirs it. (Untracked `.superpowers/` working notes also on disk.)
Action: delete or archive; drop the skip-dir entry.

### R18. No probe-table↔registry drift guard — src/probe_map.rs, prevention
The ai-family bug (fixed above) was only caught by hand. A test asserting probe_map/start_map pinned ports against port-registry.yaml would catch future port migrations mechanically.
Action: add a registry-loading test comparing table ports (skip port-0/UDS/PidFile entries).
